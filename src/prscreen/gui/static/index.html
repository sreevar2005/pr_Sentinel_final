    What prscreen does

    When someone proposes a change to a project (a pull request), prscreen reads only the lines that changed and points out anything that looks risky: leaked passwords and keys, code that runs downloaded scripts, weakened security settings, dangerous CI workflow changes, data sent to unknown sites, hidden or invisible characters, suspicious dependencies, and text that tries to trick AI reviewers.

    Each finding shows the exact line, why it may be risky, and the common harmless reasons for it. A person then decides. prscreen never runs the code it reads and never approves or blocks anything.

    How good is it?

    On 95 real merged pull requests from projects such as Django, Vite and Express it raised no medium or high finding, so it rarely cries wolf. On 65 labeled examples it caught 95% of what it should. It is a pattern tool, so a carefully written logic change can still get past it; the documentation lists those limits openly.

    The examples

    Every entry under Try a real incident is a documented real-world case, such as event-stream, ua-parser-js, Codecov, the PyTorch nightly compromise, Ultralytics, tj-actions and Toyota's leaked key, with links to the news reports and advisories. The code is a short, harmless recreation of each incident's key mechanism, not the attackers' code. One entry is an unmodified real pull request that prscreen should stay quiet on.

    Severity

    • high very likely to matter: look before merging.
    • medium worth a reviewer's attention.
    • low information, such as "CI config changed" or "new dependency".
